# UI/UX exploration

## When to use
Use when the user asks for alternative interface directions or a comparative artifact/prototype. Do not generate multiple options by default when one solution suffices.

## Procedure
1. Define user task, audience, device, available content and non-negotiable constraints. Treat proposed layout and style as preferences unless explicitly required.
2. Choose an appropriate number of directions. Vary information architecture, interaction, reading order, density, evidence access or decision flow—not merely color, shadows or corners.
3. For each direction, state what it optimizes, what it trades off, and when it is unsuitable. Do not claim user research that has not happened.
4. If authorized to build prototypes, make them comparable using the same real input or **clearly labeled** demo data. Provide a way to inspect mobile and key states when relevant.
5. Review applicable checks in `../../core/QUALITY_BASELINE.md` without enforcing one visual taste.

## Verification
A reader should be able to name a substantive difference between the directions without referring to their colors. Prototypes must not imply unsupported data insights.
