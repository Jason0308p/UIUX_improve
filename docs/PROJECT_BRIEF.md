# Project brief

## Problem
AI-generated charts and dashboards often begin with a visual pattern before defining the audience's decision or verifying that the data can support the claim. Attractive output can therefore mislead, omit context, or provide no useful next step.

## Goal
Publish reusable, agent-agnostic skills that help an AI: define the decision, assess data sufficiency, select an appropriate representation (including no chart), structure information, explore genuinely different designs, and audit results. Judge outcomes by evidence, usability, accessibility and decision support—not by a fixed aesthetic.

## Users
Conversational AI users; agent users (Claude Code, Codex, Hermes, OpenCode); analysts; PM/operations; UI/UX designers; frontend developers. Each may use just one skill. The user retains control over preferred style, density, brand, stack, output format and scope.

## MVP scope
Four independent Markdown skills, one shared quality baseline, project-level agent handoff, and a documented architecture. Subsequent work: prompt templates, profiles, adapters, examples and evaluation cases. The original planning prompt and report are reference proposals; do not silently treat every suggested rule as approved.

## Not goals
A design system, UI component library, BI platform, ETL pipeline, required dashboard layout, mandatory chart type, web app, plugin marketplace, or compulsory six-stage workflow.

## Success criteria to evaluate later
Compare outputs on the same cases with and without skills; assess unsupported claims, misleading encodings, decision usefulness and diversity of viable layouts. An attractive screenshot alone is not evidence of quality.
